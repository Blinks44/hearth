# Architecture Decision Records

Key architectural and product decisions behind Hearth v1.0.

- **Native Go UI (`mygo`) without WebView or cgo:** Hearth ships as a single native binary (~18 MB) across macOS, Windows, and Linux with native vibrancy/Mica, tray support, and deterministic UI testing via `ui.NewTester` (rejected: Electron/WebView - heavy memory footprint and separate JS toolchain).
- **Separate `tools/go.mod` for `golangci-lint`:** Pins linter version in the repo as a Go tool without polluting the application's `go.mod` / `go.sum` dependency graph.
- **Capture terminal environment instead of trusting GUI `PATH`:** On Unix, Hearth runs `$SHELL -ilc` in a detached session (`Setsid`) and parses `/usr/bin/env -0` between random markers; on Windows, it reads a fresh session block via `CreateEnvironmentBlock` and resolves junctions via `GetFinalPathNameByHandle` (rejected: inheriting GUI process env - misses Homebrew, `fnm`, `mise`, etc.).
- **Read-only scanning, confirmed operations:** Discovery never mutates the machine and never calls `mise ls --json` or remote clusters during a scan. Every system change goes through `ops.Plan` with exact commands, diffs, backups, and post-operation verification in a fresh terminal.
- **`mise` as the default version manager on clean setups:** When a user has no version manager for a language, Hearth installs and manages it through `mise` (on macOS via Homebrew) while keeping existing managers (`fnm`, `nvm`, `pyenv`, `uv`, `rbenv`, `rustup`, etc.) intact unless the user chooses to migrate.
- **First-class Colima on macOS and native Docker Engine on Linux:** Hearth offers an open-source, license-free container engine by default (Colima on macOS, distro Docker Engine on Linux) while still supporting Docker Desktop, OrbStack, Podman, and Kiri without migrating user data unasked.
- **Socket-pinned local Docker views and `docker events` watch:** Live container/image/volume/network views bind explicitly to the chosen local socket via `--host` with empty `DOCKER_CONTEXT` and never touch remote contexts. Container state changes trigger targeted `docker` + `databases` refreshes via `docker events` instead of periodic polling.
- **No background Kubernetes cluster calls:** Scanning reads merged `KUBECONFIG` files and local `kind` container labels only. Live cluster polling (`kubectl` + `client-go` JSONPath + Helm) runs strictly while the cluster viewer is open; Secrets fetch metadata only and reveal one key for 30 s on demand.
- **Safe MCP server (`hearth mcp`) with human-in-the-loop fixes:** Runs from the same binary over stdio (`github.com/modelcontextprotocol/go-sdk`), exposes strict field projections without secrets, and lets agents request standard fixes only by `issue_id` via a token-authenticated `127.0.0.1` bridge to the open window, where a human must confirm.
- **Pure Go / stdlib-first dependencies:** Beyond `mygo`, external dependencies are added only where stdlib falls short (`Masterminds/semver/v3` for npm-style ranges, `BurntSushi/toml`, `go.yaml.in/yaml/v3`, `modelcontextprotocol/go-sdk`, `k8s.io/client-go` JSONPath, `modernc.org/sqlite`). Tests use stdlib + manual fakes without mocking frameworks.
- **Shared `.agents/skills` storage and non-destructive instruction syncing:** Skills installed or deduplicated by Hearth live canonically in `.agents/skills` with symlinks to agent directories; global instruction setup creates new files (`O_EXCL`) or symlinks without overwriting existing user files.
- **Isolated `website/` package:** The landing page (TanStack Start + ModUIX on Cloudflare Workers) lives in `website/` with `paths-ignore` in Go CI and its own workflow so web edits never trigger Go desktop builds.
