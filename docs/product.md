# Hearth Product Overview

Hearth is a free, local desktop application for macOS, Windows, and Linux that gives developers one calm place to inspect, maintain, and safely configure their local development environment.

## Core Workflows

1. **Understand what is installed and active:** Distinguish what is on disk, what a new terminal runs (`PATH` order), what GUI apps see, and what each project expects.
2. **Keep projects ready:** Read project pin files statically (`.nvmrc`, `.node-version`, `package.json`, `mise.toml`, `.tool-versions`, `.python-version`, `pyproject.toml`, `go.mod`, `rust-toolchain.toml`, `global.json`, `.ruby-version`, `composer.json`, `*.tf`, Compose, and Kubernetes manifests) and install missing runtimes or tools without silently changing global defaults.
3. **Inspect and control local infrastructure:** Manage local Docker engines (with first-class Colima support on macOS and native Docker Engine on Linux), containers, images, volumes, networks, Kubernetes clusters, local databases, listening TCP ports, and cloud CLIs.
4. **Manage AI coding agents:** Inspect installed agents, shared/per-agent skills, curated skills catalogs, MCP servers, global/project instruction files, plaintext-secret warnings, and local token usage / estimated cost.
5. **Maintain a clean machine:** Surface actionable issues ("Needs attention"), runtime and package-manager updates, shell startup bottlenecks, and safe disk cleanup with transparent explanations.

## Feature Map

### Overview, Projects & New Computer Setup
- **Overview:** Status hero, live environment strip (Docker, Kubernetes, Databases & Ports, AI today, MCP), top issues with one-click fix plans, tool cards, compact project summary, and copyable secret-free diagnostic report.
- **Projects:** Discover folders from common dev directories or add manually; inspect every tool requirement, linked Kubernetes context, project databases, running services, and AI configs; run and manage project scripts (`package.json`, `Makefile`, `Taskfile.yml`, `justfile`, `mise.toml`, `composer.json`) with live streaming logs and clean process-group teardown; prepare a project with a dependency-aware multi-step plan and post-scan verification.
- **Install / New Computer:** Guided setup on fresh machines and catalog install on configured machines. Defaults to `mise` for languages when no version manager is present, supports picking specific versions for `mise` languages and versioned database packages, respects existing managers, and supports exporting/importing setup bundles across machines.

### Languages & Runtimes
- **Node.js, Bun, Python, Go, Rust, PHP, Java, Ruby, .NET, C/C++:** Full version tables with source badges (`mise`, `fnm`, `nvm`, `volta`, `uv`, `pyenv`, `rustup`, `rbenv`, `sdkman`, `brew`, `winget`, `scoop`, `apt`, etc.), `which -a` resolution traces, EOL and installed release markers, custom version spec installation, manager cards, global packages/toolchains with update/remove plans, and online available-version lists.
- **JS package managers (`npm`, `pnpm`, `Yarn`, Corepack)**, **Composer**, **Git** (whitelisted global config, `credential.helper=store` migration plan, `gh` hosts and `gh auth login` terminal launch, SSH public keys with `ssh-add` launch without reading private keys), **Editors** (VS Code, Cursor, Devin Desktop/Windsurf, JetBrains IDEs - CLI `PATH` setup, extension lists and search, old versions, index caches with inline cleanup), and **Mobile** (Xcode switching, runtimes & DerivedData, Android SDK/AVDs, `ANDROID_HOME`/`JAVA_HOME` shell plans, Flutter/pub caches).

### Infrastructure
- **Docker:** Contexts, engines, projects, plugins, and `PATH`. First-class Colima management on macOS (install, standalone CLI, Compose/Buildx plugins, VM resources, disk reclaim, autostart) and native Docker Engine on Linux. Live local engine view: Overview (clickable recent events), Containers (grouped by Compose project, live stats, browser launch for HTTP ports, details, masked Env with 30 s single-value reveal, streaming logs, terminal shell), Images (pull, untag, remove), Volumes, and Networks (search across tabs and clickable "Used by" links).
- **Kubernetes:** Merged `KUBECONFIG` contexts (no background cluster calls during scan), starter/pasted `~/.kube/config` creation, kubeconfig editor links, context deletion, explicit access checks, local `kind` clusters with direct cluster open, project-to-context links, and live cluster view: Overview, Pods (grouped by owner, factual diagnosis, streaming logs, pod/owner logs, shell, `127.0.0.1` port-forward with browser launch and reconnect), Deployments (scale, restart, pause/resume, rollback), Jobs/CronJobs, Services, ConfigMaps, Secrets (metadata only; single-key 30 s reveal), PVC/StorageClasses, Nodes (cordon/drain), HPA/PDB/Quotas, Namespaces, CRDs, Helm releases, RBAC `can-i`, and server-side dry-run manifest apply.
- **Databases & Ports:** Local PostgreSQL, MySQL/MariaDB, Redis, MongoDB, SQL Server, and SQLite servers/services/containers with project attribution, port-conflict detection against Compose files, one-click OS service install/autostart/start/stop/restart, terminal CLI launch, and listening TCP port inspector with static dev-server framework classification, CPU/memory metrics, HTTP browser-open checks, and managed project-script / `kubectl` port-forward integration.
- **CLI & Clouds:** `aws`, `gcloud`, `az`, `terraform`, `tofu`, common CLI utilities (`jq`, `ripgrep`, `fzf`, `just`, `k9s`, `direnv`, `deno`), and `mise` tools (with update/remove plans) - active profile/project/subscription, explicit identity check, native login launch, and clickable project Terraform/OpenTofu version checks.

### AI Ecosystem
- **Agents & Live Radar:** Claude Code, Codex, Cursor, GitHub Copilot CLI, Gemini CLI, OpenCode, Antigravity CLI, Devin, Grok Build, Kimi Code - versions, configs, hooks/permission summaries, passive live process radar, opt-in lifecycle hooks (`hearth notify`) with confirmed diff plans and desktop notifications when an agent waits for input or finishes.
- **Skills:** Unified view across agents and projects, shared `~/.agents/skills` canonical storage with agent symlinks, duplicate detection/deduplication, and public catalog browser (Anthropic, OpenAI, Vercel, `skills.sh`).
- **MCP:** Aggregated user and project MCP servers across agents, conflict detection, plaintext secret detection with "Move to env var" migration plans, and one-click connection of Hearth's own MCP server (`hearth mcp`) exposing secret-free read tools (`get_summary`, `get_tool`, `get_projects`, `get_issues`, `get_path`, `get_docker`, `get_ports_and_databases`, `get_skills`, `get_kubernetes`, `get_cleanup`, `get_usage`, `get_models`, `get_instructions`, `get_ai_quotas`), resources (`hearth://summary`, `hearth://projects`, `hearth://issues`, `hearth://ports`), prompts (`diagnose-project`, `troubleshoot-port`, `audit-ai-setup`), and human-in-the-loop proposal tools (`propose_fix`, `propose_project_prepare`, `propose_stop_process`, `propose_service_action`, `propose_skill_action`, `propose_tool_install`, `propose_cleanup`).
- **Quotas & Limits:** Cross-platform read-only subscription and rate-limit monitoring across 18 AI providers (Claude Code, Codex, Antigravity, Gemini CLI, Cursor, GitHub Copilot, JetBrains AI, Grok, Windsurf, Cline, Kimi, OpenCode Go, Kiro, Kilo, Amp, Augment, CodeRabbit, HuggingFace) with canonical window ordering (`5h` before `Weekly`), inline reset times/dates, burn-pace markers, projected depletion, progressive refresh updates, adaptive polling (2 min while open, 0 background calls when notifications are off, 5-15 min or sleep-until-reset when notifications are on), stale-cache fallback with strict 429 cooldowns, per-provider tray visibility and ordering, and optional debounced low-quota (`<10%`) / reset desktop notifications.
- **Instructions, Local Models & Usage:** Global (`~/.agents/AGENTS.md` sync) and project instruction files; Ollama and LM Studio models (pull, unload, remove, server start/stop); local session token/cost analytics from agent history files.

### System & Maintenance
- **Issues ("Needs attention"):** Actionable problems across `PATH` (missing, duplicate, relative), version mismatches, Docker, Kubernetes, secrets, and shell startup, with hide/restore support.
- **Updates & Package Managers:** Unified runtime/tool updates and two-level OS package manager workspace (Homebrew, WinGet, Scoop, Chocolatey, APT, DNF, Pacman, Zypper, APK, Snap, Flatpak, Nix): direct entry into the active manager, per-OS Available managers catalog with official install plans, Overview/Packages/Updates/Dependencies/Install views, split-view package inspector, bulk upgrades/removals, safe autoremove of unused dependencies, index refresh, and explicit user-triggered catalog search.
- **Cleanup:** Reclaimable disk space across unused tool versions, package/build caches, Docker disk usage, old editor extensions/caches, simulator runtimes, stale AI history (>90 days), and unused local models (>=1 GB).
- **PATH & Shell Startup:** Terminal vs. GUI `PATH` comparison, source file/line attribution, add/remove/reorder entries with rollback verification, macOS `launchctl` PATH sync, and zsh/bash/fish/PowerShell startup profiling with proportional waterfall bars, on-demand re-measurement, and `nvm` -> `mise` migration.
- **Tray / Menu Bar & Settings:** Native menu bar / tray control-center popover with configurable section order and visibility (running dev servers, Docker containers, local databases, Kubernetes port-forwards, compact AI subscription quotas, Colima toggle, and quick Docker/Kubernetes context switching) alongside the classic right-click menu; optional macOS Dock icon hiding when closed to menu bar; 6 UI languages (`en`, `de`, `es`, `fr`, `ru`, `zh-Hans`); light/dark/system themes; signed auto-updates.

## Boundaries

Hearth intentionally does **not**:
- Run commands or edit files without showing a plan and waiting for confirmation (except explicit quick context switches from the native tray menu).
- Upload telemetry, require an account, or transmit user code, secrets, or environment variable values.
- Install application dependencies (`node_modules`, `.venv`, Cargo crates) or act as a database query GUI / code editor.
