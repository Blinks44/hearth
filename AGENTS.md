# AGENTS.md

Instructions for AI coding agents working on the Hearth repository (`CLAUDE.md` imports this file via `@AGENTS.md`).

## Project Overview

Hearth is a free local desktop application (macOS, Windows, Linux) that shows installed dev tools, `PATH` resolution, project version pins, local Docker/Kubernetes/databases, and AI coding agents (skills, MCP, instructions, usage), and applies fixes or installations only after showing a plan and diff.

Stack: **Go 1.27.3+**, [mygo](https://mygo.egoist.dev) v0.10 (native immediate-mode UI, no cgo, no WebView). Prefer Go stdlib and `golang.org/x/*` before introducing third-party dependencies.

```
main.go                 entry point: window, tray, and `hearth mcp` dispatch
internal/               application packages (see docs/architecture.md)
locales/                UI string catalogs: en.json (source), de, es, fr, ru, zh-Hans
resources/              app & tray icons, embedded fonts, SVG icons, NOTICE.txt
e2e/                    end-to-end test driving the built binary (`-tags e2e`)
website/                landing page (TanStack Start + ModUIX), isolated CI
docs/                   architecture, product overview, invariants, design tokens, ADRs, roadmap
tools/go.mod            dev tools (golangci-lint), separate from app dependencies
.agents/skills/         agent skills (.claude/skills symlinks to them)
```

## Commands

Run from the repository root (on Windows without `make`, use the equivalent commands in [README.md](README.md#building-from-source)):

- `make dev` - live-reload desktop window (`go tool mygo dev`; localized UI: `go tool mygo dev -lang ru`)
- `make check` - full CI suite (`golangci-lint fmt --diff`, `golangci-lint run`, `mygo vet`, `mygo i18n check`, `go test -race` + `./internal/ui`): **run before finishing work**
- `make test` / `make lint` / `make fmt` - individual checks
- `make e2e` - end-to-end test with the `automation` plugin (`e2e/`, requires a desktop session)
- `make build` - release bundle for the current OS in `build/<os>-<arch>/`

Generated or local paths (do not edit generated files by hand): `locales/catalog_gen.go` (generated by `mygo dev` / `mygo generate` from `locales/*.json`; committed), `build/`, `.mygo/`, `.local/`.

## Architecture & Coding Rules

- Follow package boundaries in [docs/architecture.md](docs/architecture.md) and preserve all invariants in [docs/domain.md](docs/domain.md).
- Discovery is strictly read-only. Every mutating action goes through `internal/ops` with an explicit `Plan`, preview, and user confirmation.
- Never do I/O or spawn processes on the UI thread. Publish background results exclusively through `win.Update(...)`. Keep view functions pure and never store `ui.Element` in state.
- Execute external commands only through `internal/run` (explicit `argv`, `ctx`, timeout, output cap) - never via shell strings.
- Read terminal/GUI environments and `PATH` only through `internal/sysenv` (GUI process env != terminal env).
- Split OS-specific code using Go build-suffix files (`_darwin.go`, `_windows.go`, `_linux.go`, `_unix.go`) rather than branching on `runtime.GOOS` inside logic.
- All user-visible UI strings must come from `locales/` (`en.json` is the source catalog), not hardcoded literals.
- Wrap errors with `fmt.Errorf("...: %w", err)`. A single failing detector must never abort a scan.

## Principles

- Keep solutions simple and readable; avoid speculative abstractions, unused settings, or over-engineering.
- Prefer built-in `mygo` / Go stdlib functionality over custom code.
- Respect user setups: detect the owning manager (`mise`, `fnm`, `brew`, `winget`, `apt`, ...) and work through it. Edit user shell rc files only inside `# >>> hearth >>>` / `# <<< hearth <<<` markers with backups and diffs; lines outside the block may only be commented out (never deleted) after confirmation.

## UI & UX Guidelines

- Check [docs/design.md](docs/design.md) for color tokens, window chrome rules, and recurring patterns before changing UI.
- Keep action buttons, row heights, icon sizes, and column grids aligned across sibling screens.
- Verify long names, localization strings (`en` and `ru` at minimum), empty/loading/error states, scrolling, and both standard (`1280x820`) and narrow (`1000x680`) window sizes. Lock important layout geometry in `ui.NewTester` tests.

## Testing

- Logic (`sources`, `projects`, detectors, parsers, operations): table-driven stdlib tests with fixtures in `testdata/`, fake `run.Runner`, and `t.TempDir()`. Real shell/OS tests use `//go:build integration`.
- UI: `ui.NewTester` against fake `inventory.Snapshot` fixtures.
- Test meaningful behavior and invariants rather than chasing coverage percentages.

## Git & Documentation

- Write code, comments, documentation, and commit messages in English.
- Use Conventional Commits (`feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`).
- Never commit secrets, personal hostnames, IPs, cluster names, emails, or machine-specific paths. Keep temporary scratch files in `.local/` (gitignored).
- Update [docs/product.md](docs/product.md), [docs/domain.md](docs/domain.md), or [docs/decisions.md](docs/decisions.md) when user-facing behavior, invariants, or architectural decisions change.
